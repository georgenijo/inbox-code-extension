# Inbox Code privacy

Inbox Code connects directly from your browser to Google's Gmail API with Gmail read-only permission. That permission technically allows reading your mailbox; Google does not provide a verification-code-only permission.

The extension searches recent verification-related messages. It checks sender metadata and Gmail authentication results, then reads bodies only for candidate senders that match the website you are using. It extracts short-lived codes locally. It does not send email, change messages, delete mail, or mark messages read.

No email, code, or token is sent to an Inbox Code server. There is no analytics, advertising, external AI processing, or sale of data. Gmail-derived information is used solely to provide the user-facing code-filling feature, consistent with the Google API Services User Data Policy, including Limited Use requirements.

OAuth access tokens are stored only in trusted extension session memory, not persistent extension storage, and are cleared on browser restart or disconnect. The extension stores your connected email address and disabled websites and optional sender-domain overrides locally. Candidate codes and message identifiers are held temporarily in memory. Consumed message identifiers are retained in extension-only session storage until their five-minute expiry to avoid offering an already used code after a worker restart. A suggested code is visible in the website DOM once offered; the destination website can read filled values. The extension has HTTPS website access and runs by default on supported top-level HTTPS pages. It searches Gmail only while a detected code field is active. You can turn suggestions off for an exact website origin from the popup. Known shared-content hosts do not inherit their platform mail domain automatically; the user may explicitly override the sender for a trusted host. Sender-domain matching prevents arbitrary unrelated sites from receiving another domain’s codes; shared login/email providers cannot always distinguish individual login attempts. Cloudflare Access matches the dedicated `notify.cloudflare.com` sender, which is shared across teams, so review the destination team before filling. The suggestion host is visible in the page DOM; a page can detect the extension and infer suggestion/connection activity from its presence or size.

Disconnect removes the local account connection and cached tokens and attempts to revoke Google's access grant. Site settings remain until removed. Uninstalling removes extension storage. You can independently revoke access in your Google Account's third-party connections.

This development version is not published in the Chrome Web Store. Before public distribution, publish this policy with an actual support contact and complete the applicable store and Google reviews.
